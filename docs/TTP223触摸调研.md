# TTP223 触摸不灵敏：GitHub 调研与本机排查

**建议先测模块 OUT 是否能稳定跟随手指，再决定改硬件还是改手势。** 目前不建议再缩短去抖或直接换库。

## 本机证据

- OUT 接 GPIO4，串口曾记录到两组完整的高低电平变化和成功双击；因此模块到 ESP32 的链路至少有时是有效的。
- 另有 GPIO4 持续高电平数秒的记录。串口没有同步标记实际松手时间，因此不能据此直接认定自锁、模块故障或供电干扰。D1 的丝印也不能证明它接的是电源还是 OUT。
- 现有手势参数为 15 ms 去抖、450 ms 双击窗口、800 ms 长按。原始 GPIO 变化和判定是两个不同层面。试播程序在播放时交替轮询触摸并写 I²S；正式程序将手势采样放在主循环，但语音忙时不会接收新手势。忙时无响应是正式版交互策略，不能用于解释试播版的现象。

## GitHub 证据

1. [SmallOLED-PCMonitor](https://github.com/Keralots/SmallOLED-PCMonitor#touch-button-control) 在 ESP32 上把 TTP223 当成 3.3 V 数字输入，使用独立的去抖和多击窗口。其 README 给出最后一次松开后约 350 ms 的计数窗口。不同手势计时定义不能仅按数值横向对比。
2. [OneButton](https://github.com/mathertel/OneButton#event-timing) 明确区分按下反馈和单击确认；启用双击后单击必然等待。默认双击 400 ms、长按 800 ms。它也支持仅对松手去抖，从而让按下反馈更快；这不能补回传感器没有输出的边沿。
3. [乐鑫 IoT Button 源码](https://github.com/espressif/esp-iot-solution/blob/master/components/button/iot_button.c) 用独立定时器周期采样 GPIO，再用连续采样和状态机识别手势。可借鉴的是让采样与播放器、网页请求解耦，而不是直接增加依赖。
4. [Tasmota #3433](https://github.com/arendst/Tasmota/issues/3433) 是安装环境变化后自触发的个案，评论指出原发帖者把电源去耦电容和感应灵敏度电容弄混了。不能把 22 pF 当成通用修复，更不能不确认焊盘就换件。
5. [通泰 TTP223E-BA6 手册](https://www.tontek.com.tw/uploads/product/128/TTP223E-BA6_V1.0_EN.pdf) 说明该型号在 3 V 低功耗条件下响应最长约 220 ms，且支持瞬时/翻转以及有效电平配置。手头模块芯片版本未确认，这个上限不能当成实测延迟。

## 推荐排查顺序

1. 先关闭功放供电做静态对照，触摸模块仍用 ESP32 的 3V3 供电；断电操作，功放信号接线的处理以避免断电功放被信号反向供电为准。触摸线插牢，正面圆片直接操作。空手上电等待约 2 秒。
2. 记录 10 次单触和 10 组双触。至少区分手指动作、GPIO4 原始边沿、确认边沿和手势结果。记录漏掉的第几下，不以 D1 亮灭代替输出判断。
3. 若原始 OUT 不回落或漏边沿，先确认模块瞬时模式、VCC/GND/OUT、接头、触摸面和安装环境。重复同样的试验对照功放启用与播放时的表现。仅播放时恶化才提高电源噪声和采样阻塞的优先级；两者需要分别验证。
4. 若原始边沿完整但手势仍漏，先测现有轮询的最长间隔；需要时改为独立定时采样（例如每 5 ms）并把手势事件交给主循环。若手势准确但感觉迟钝，可在确认按下时先给轻反馈，在点击窗口结束后才执行学习/休息动作。
5. 没确认具体型号和焊盘前，不拆电容、不短接 A/B、不把 OUT 改接到 5 V。若同一块模块裸板、独立测试仍不能可靠区分短触，可以换一块确认是瞬时型的模块或用实体按钮作为演示对照。

本次为只读调研；没有改固件、烧录或修改接线。
