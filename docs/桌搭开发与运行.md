# 学伴桌搭：双模式语音与计时

当前硬件：ESP32-S3 N16R8、GPIO4 的 TTP223、GPIO10/11/12 的 INMP441、GPIO13/14/15 的 MAX98357A 和扬声器。超声波、光敏、OLED 和电池均非必需。功放完成接线前，只能通过串口和网页观察。

联网后语音对话默认常驻开启，不再需要触摸任何模块。学习中、休息中、空闲和正在计时时都可以直接说话；用户询问一般问题时由云端模型回答，要求设置、查询或停止计时时由模型调用板端计时接口。

触摸模块不再参与对话触发，也不会产生额外的收音提示音。串口事件依次显示 `ALI_LISTENING`、`ALI_SPEECH_START`、`ALI_SPEECH_STOP`、`ALI_HEARD`、`ALI_REPLY` 和 `ALI_FIRST_AUDIO`，可据此区分听不到语音、无效语音轮次和音频播放问题。局域网页也可直接设置专注/休息时长（1–120 分钟）或停止。专注到点播鼓励语，随后可以播音乐；休息到点播回归提醒。正在播报时会静音上传麦克风，提示音与播报串行执行。

## 先烧录和做离线测试

以下命令在本项目根目录用普通 Windows PowerShell 运行：

~~~powershell
.\tools\Build-DeskBuddy.ps1
.\tools\Build-DeskBuddy.ps1 -Flash -Port COM18
~~~

首次编译会从乐鑫 GitHub 获取中文 MultiNet7，校验文件后用乐鑫工具打包。烧录包含主程序和独立模型分区，不用自己训练或安装额外的语音库。当前 PC 是 Arduino ESP32 core 3.3.11；N16R8 配置为 16 MB QIO Flash、8 MB OPI PSRAM。固件的分区表由草图目录的 partitions.csv 提供。本版主固件串口用 921600；早期 Wi-Fi 和麦克风单测草图仍用 115200。开机先断开网络，测试「开始专注」和「停止计时」；预期看到 OFFLINE 日志。没有音频包时用不同音高提示，麦克风现场识别需要实测。

## 配置模型后端

先在一台与设备互通的电脑上运行后端。以下两个值只在当前 PowerShell 会话内使用：

~~~powershell
$env:OPENAI_API_KEY = [Net.NetworkCredential]::new('', (Read-Host 'OpenAI API key' -AsSecureString)).Password
$env:DESKBUDDY_DEVICE_TOKEN = [Guid]::NewGuid().ToString('N')
$env:DESKBUDDY_DEVICE_TOKEN
python backend/server.py
~~~

用另一个 PowerShell 执行：

~~~powershell
.\tools\Configure-DeskBuddy.ps1 -Port COM18
~~~

依次输入 Wi-Fi 名称、密码、后端地址（例如 http://电脑局域网IP:8765）、刚生成的设备令牌。ESP32 接 2.4 GHz；电脑可继续用同一路由器的 5 GHz，只要局域网没有隔离。串口输出 DESKBUDDY_IP 后，浏览器访问该地址看计时界面。正常 Wi-Fi 配网会保存到板端，重启后自动连接；USB 临时模式不会覆盖已保存的网络配置。模型密钥留在电脑端。后端供可信局域网调试使用，不将端口直接暴露到公网；POST /voice 需要设备令牌。

默认后端采用 OpenAI 的转写和合成接口；对话模型默认 gpt-4.1-mini。若要换兼容模型服务，可在启动后端前设置 DESKBUDDY_MODEL_BASE_URL、DESKBUDDY_MODEL_API_KEY、DESKBUDDY_MODEL；该服务需支持 Chat Completions 的严格 JSON Schema。可用 DESKBUDDY_STT_MODEL、DESKBUDDY_TTS_MODEL、DESKBUDDY_VOICE 调整 OpenAI 音频参数。联网模型通过 MCP 查询和控制板端计时；ESP32 校验时长，若网页先改了计时，设备拒绝旧请求。对话上下文保存在后端内存，仅保留最近六轮，后端重启会清除。

## 更换本地语音和音乐

把 [audio](../audio/) 中列出的文件按需放入 audio 目录。统一格式为 **24 kHz、单声道、16 位有符号小端原始 PCM**（不是把 MP3 或 WAV 改扩展名）。可用 Audacity 导出原始 PCM，或安装 FFmpeg 后转换：

~~~powershell
ffmpeg -i 你选的音频.mp3 -ac 1 -ar 24000 -f s16le audio/focus_done.pcm
.\tools\Build-DeskBuddy.ps1 -Flash -FlashAudio -Port COM18
~~~

FlashAudio 会替换板上的整份音频分区；把还想保留的音频一起留在 audio 目录再执行。音乐建议先用短片段。素材由你挑选，仓库只带提示音和文件名约定。

## 复用的开源实现

- [乐鑫 ESP-SR](https://github.com/espressif/esp-sr)：直接调用 MultiNet 中文命令识别引擎，使用官方模型与打包器；[中文口令文档](https://docs.espressif.com/projects/esp-sr/zh_CN/latest/esp32s3/speech_command_recognition/README.html)。
- [Arduino ESP32](https://github.com/espressif/arduino-esp32)：复用 I²S、Wi-Fi、WebServer、HTTPClient 和 LittleFS。
- [小智 ESP32](https://github.com/78/xiaozhi-esp32)：参考设备采播与服务端对话分工。此版保留现有引脚和本地计时，使用自己的 HTTP 接口，未引入小智固件或云协议。
- 云端链路参考 [OpenAI 官方语音代理文档](https://developers.openai.com/api/docs/guides/voice-agents)。

## 功放未接时：电脑联调页 + DeepSeek

本机准备过 faster-whisper 后，运行：

~~~powershell
.\tools\Start-VoiceDashboard.ps1 -Port COM18
~~~

其他电脑第一次运行可加 -Prepare 安装 pyserial、faster-whisper 和本地多语言 base 模型。打开 http://127.0.0.1:8765/。先填 DeepSeek API Key，可用「测试模型」只发文字测模型响应；然后填写设备 Wi-Fi 连接参数，启用电脑播报，用触摸开启实际语音对话。后端占用 COM18，烧录或另开串口监视器前须停止它。

DeepSeek 使用 https://api.deepseek.com，默认 deepseek-flash，JSON Output 并关闭思考模式；它负责对话和计时意图，电脑本地负责中文转写，浏览器负责播放中文回复。这个组合只需要 DeepSeek 的 Key；不需要 OpenAI Key。配置通过电脑本地页面写入后端进程内存，重启后重新填。浏览器没有可用中文语音时，仍能看文本。

联调页的「采集」是板上固定 5 秒收音窗口。「设备请求往返」从板子发音频到收到后端响应头；「转写」「模型」「后端总计」分别由电脑实测。这几个数据有包含关系，不应相加。电脑播报耗时不包含在设备往返里。没有 API Key 时，仍可看到触摸、麦克风峰值和本地转写，但不能完成模型回复。

联调固件的 COM 串口使用 **921600**。找不到目标 Wi-Fi 时，可以让设备用 USB 传输音频，电脑继续联网调用 DeepSeek：在联调页留空 Wi-Fi 名称，发送本次会话设置即可。此时页面标记 USB；这条路径的耗时不能当作 Wi-Fi 延迟。脱离电脑、又不联网时仍走板上的离线口令。


## 喇叭联网对话与试听

Windows 测试机使用已安装的普通话音色（慧慧、康康、瑶瑶）。本地联调页的试听使用同一句提醒，点「选用」后下一轮桌搭播报才使用所选音色。默认慧慧仅用于试跑；音色选择保留在当前后端进程。后端环境设 DESKBUDDY_TTS=windows 和 DESKBUDDY_PC_AUDIO=0 时，语音回复会回到板子；电脑播报模式则仍可使用浏览器音色。

设备未接入 Wi-Fi 时，COM18 可双向传输音频：桌搭麦克风 → 电脑本地转写 → DeepSeek → Windows 合成 → 桌搭喇叭。此时电脑负责联网。设备播放输出为 48 kHz，素材和后端接口仍用 24 kHz PCM。串口日志 UI usb_audio 是设备收到完整回复音频的耗时，UI speaker_play 表示开始写入 I²S；实际发声需要现场确认。


## 口语提示词和 MCP

每轮都加载 [桌搭提示词](../backend/deskbuddy-prompt.md)。默认一两句口语，问候和聊天不用工具；只说要定时却没给时长时先追问。计时成功确认使用板端返回值。

- 语音请求由板子通过 Wi-Fi 发到局域网后端，后端通过 HTTPS 调 DeepSeek，并在本机运行 MCP 客户端。
- [timer_mcp.py](../backend/timer_mcp.py) 是标准 stdio MCP 服务，提供 start_timer、stop_timer、get_timer。独立运行时由 MCP 客户端设置 DESKBUDDY_BOARD_URL 和 DESKBUDDY_DEVICE_TOKEN；模型不能指定板端地址或令牌。
- 板端 GET/POST /api/timer 使用设备令牌。语音发起时附带计时版本，旧状态上的修改请求返回 HTTP 409。手机或电脑网页仍可以手动计时。
- 第一次启动联调用 .\tools\Start-VoiceDashboard.ps1 -Port COM18，打开 http://127.0.0.1:8765/ 配网。成功后给板子单独供电即可；正式启动后端 .\tools\Start-VoiceDashboard.ps1 无需指定串口。后端需要可达的局域网地址和 DeepSeek API Key；电脑 IP 变化时需要重新配网或给电脑固定 DHCP 地址。
- 串口仅用于首次配网、烧录和诊断。若板端不在局域网，USB 临时对话仍可聊天，但没有板端地址时不能通过 MCP 计时。设备令牌由启动脚本在 .build 中保持一致；DeepSeek Key 不进固件。

## 百炼实时语音板端直连

模型：qwen-audio-3.1-realtime-flash。ESP32 通过加密 WebSocket 常驻采集并发送 16 kHz 单声道音频到百炼；服务端检测说话结束，设备边收到回复边播。设备播放采样率为 48 kHz；音色暂用 longanqian_v3.1。板端直接执行 start_timer、stop_timer、get_timer，旧的电脑 MCP 工具继续可用于调试。

当前工作区的 .build/arduino-libs 已准备 arduinoWebSockets 2.7.2 和由 ESP32 工具从 CA 集合生成的 DeskBuddyTls 库。配置百炼用 .\tools\Configure-AliVoice.ps1；Key 在串口传入并保存于板端配置，不写进源文件。网络配置完成后直接说话即可，电脑不参与语音。设备连接云端后持续监听并复用对话上下文，不再播放开始收音提示音。固件提示词在 firmware/DeskBuddy/CloudPrompt.h，来源为 backend/deskbuddy-prompt.md，变更后需要重新编译烧录。

延迟从串口 ALI_SPEECH_STOP 到 ALI_FIRST_AUDIO 读出；这个指标不含云端检测停顿所需的约 500 毫秒，也不等于实测物理发声时间。云端直连失败时有错误日志和短音提示。
